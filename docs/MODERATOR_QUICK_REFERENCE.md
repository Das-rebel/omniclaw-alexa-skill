# Moderator Quick Reference Guide
## OmniClaw 2.0 Usability Testing

**Version**: 1.0
**Date**: 2026-04-19
**For**: Test Moderators

---

## 🎯 Your Role

As a moderator, your job is to:
- Facilitate smooth test sessions
- Observe and document user behavior
- Remain neutral (don't lead or influence)
- Intervene only when necessary
- Create a comfortable environment

**You are NOT**:
- Testing the participant (you're testing the system)
- Showing them how to use features
- Expressing opinions about performance
- Leading them toward "correct" answers

---

## ⏱️ Session Timeline (60 minutes)

| Time | Phase | Key Actions |
|------|-------|-------------|
| 0-5 min | Introduction | Welcome, consent, background questions |
| 5-15 min | Scenario 1 | First-time interaction |
| 15-30 min | Scenario 2 | Complex multi-step task |
| 30-40 min | Scenario 3 | Error recovery |
| 40-50 min | Scenario 4 | Feature discovery |
| 50-55 min | Scenario 5 | Platform tests (quick rotation) |
| 55-60 min | Debrief | Survey, feedback, wrap-up |

## 📋 Opening Script (2 minutes)

```
"Welcome and thank you for joining today!

We're testing OmniClaw 2.0, a personal assistant that you can talk to
via Alexa, WhatsApp, or the web interface.

**Important things to know:**
• There are NO wrong answers - we're testing the system, not you
• Please think out loud as you complete tasks
• Tell me what you're thinking, expecting, and feeling
• If you get stuck, it's okay to ask for help
• Your screen/voice will be recorded for analysis
• You can stop at any time without penalty

I'll be observing and taking notes. I won't be able to answer your
questions during the tasks, but I'll explain why after we finish.

Let's start with a few quick questions about you..."
```

**Then ask:**
1. What do you do for work?
2. How do you typically use voice assistants?
3. [If current user] How long have you used OmniClaw?

## 🎤 Moderation Principles

### ✅ DO:
- Stay neutral in tone and expression
- Take detailed notes on behavior and emotions
- Use active listening ("I see", "Interesting")
- Notice and document non-verbal cues
- Keep session on timeline
- Intervene if stuck > 3 minutes

### ❌ DON'T:
- Lead participant toward specific actions
- Show them how to use features
- Express opinions ("Good job!", "That's right")
- React to errors or frustrations
- Answer questions about the system
- Demonstrate capabilities

### 💬 PHRASES TO USE:
- "Tell me what you're thinking"
- "What do you expect to happen?"
- "Is that what you expected?"
- "How confident do you feel?"
- "Continue whenever you're ready"

### 🚫 PHRASES TO AVOID:
- "Try saying X" (leading)
- "You're doing great!" (reinforcement)
- "Actually, you should..." (instruction)
- "Let me show you..." (demonstration)

## 🔄 Task Transitions

**Moving between scenarios:**

```
"Great, let's move to the next task."
"Perfect! Here's your next challenge."
"Thanks for that. Now let's try something different."
```

**If participant completes task quickly:**
```
"That worked well. Let's try the next scenario."
```

**If participant is struggling (but not stuck >3min):**
```
"Take your time. There's no rush."
"Tell me more about what you're trying to do."
```

---

## 🚨 Intervention Protocol

**When to Intervene:**
- Participant stuck for > 3 minutes on same step
- Technical issue preventing progress
- Participant shows high distress
- Participant explicitly asks for help
- Safety concern (unlikely)

**Intervention Script:**
```
"I notice you've been working on this step for a few minutes.
Would you like some guidance, or would you prefer to try a
different approach?"
```

**If they accept guidance:**
- Provide minimal hint to unblock
- Don't show full solution
- Continue observing

**If technical issue:**
```
"I'm seeing a technical issue. Let's take a quick break
and sort this out."
```
- Resolve issue or skip to next task
- Note technical problem in data collection

## 📊 Data Collection - What to Record

### Quantitative (in template):
- ⏱️ Time to first action (use stopwatch)
- ✅ Task completion (Y/N)
- 🔄 Number of turns
- ❌ Errors encountered
- 😊 Confidence ratings (1-5)

### Qualitative (in notes):
- **Verbalizations**: What they say while thinking aloud
- **Emotions**: Frustration, delight, confusion, surprise
- **Behavior**: Click patterns, hesitation, exploration
- **Quotes**: Exact quotes for insights (use quotation marks)

### Observation Codes:
Use these shorthand codes in notes:
- ⏸️ **PAUSE** - Participant stops/thinks
- ❓ **CONF** - Confusion evident
- 😊 **POS** - Positive emotion
- 😞 **NEG** - Negative emotion
- 💡 **AHA** - Moment of discovery
- 🔄 **RETRY** - Retries action
- ⏭️ **SKIP** - Skips/gives up
- 🎯 **SUCCESS** - Task completed successfully
- ❌ **FAIL** - Task failed

## 🎯 Scenario-Specific Guidance

### Scenario 1: First-Time Interaction
**Watch for:**
- Where they start (platform choice)
- How quickly they engage
- Initial confidence level
- First action taken

**Note:**
- Time from "start" to first input
- Any hesitation or confusion
- What prompts their first action

### Scenario 2: Complex Multi-Step
**Watch for:**
- How they phrase requests
- Natural language vs. specific commands
- Understanding of context
- Persistence through steps

**Note:**
- Each sub-task completion
- Number of turns per task
- Any context confusion

### Scenario 3: Error Recovery
**Watch for:**
- Reaction to error message
- Understanding of what went wrong
- Recovery strategy
- Time to recovery

**Note:**
- Exact error message received
- Whether they understand it
- How they recover (rephrase, give up, etc.)

### Scenario 4: Feature Discovery
**Watch for:**
- Exploration patterns
- Accident discoveries
- What capabilities they find
- Estimated vs. actual capabilities

**Note:**
- List each capability discovered
- How they discovered it
- What they think exists but haven't found

### Scenario 5: Platform Tests
**Watch for:**
- Ease of use per platform
- Response appropriateness
- Natural fit for platform
- Platform preference

**Note:**
- Which platform feels most natural
- Any platform-specific frustrations

```
## 🆘 Troubleshooting

### Participant is shy/quiet:
``"Remember to think out loud - I can't hear your thoughts!
Tell me what you're considering or expecting."
```

### Participant asks "Is this right?":
``"There are no right or wrong answers. I'm interested in
how you approach this, not whether you get it 'right'."
```

### Participant asks "How do I...?":
``"That's a great question. For this test, I can't answer,
but try your best and see what happens."
```

### Technical issue occurs:
1. Acknowledge: "I'm seeing a technical issue"
2. Pause: "Let's take a quick break"
3. Resolve: Fix or skip to next task
4. Document: Note issue in data collection
5. Continue: "Thanks for your patience, let's continue"

### Participant wants to quit:
1. Validate: "I understand this is frustrating"
2. Encourage: "We have just a few more minutes"
3. Optional: "We can skip this task if you prefer"
4. Respect: If they insist to stop, respect their decision
5. Compensate: Provide prorated compensation

## 🎯 Success Indicators

**Good session indicators:**
- ✅ Participant spoke thoughts aloud
- ✅ Completed most scenarios
- ✅ Provided honest feedback
- ✅ Minimal moderator intervention
- ✅ Data collection complete

**Red flags:**
- ❌ Participant frequently looked to moderator for validation
- ❌ Moderator had to intervene multiple times
- ❌ Technical issues disrupted flow
- ❌ Data collection incomplete

**If red flags occur:**
- Note in session report
- Consider whether data is usable
- May need to replace participant

## 🧠 Reminder: Core Principles

1. **Neutral Observation**: You're a fly on the wall
2. **Think Aloud**: Their thoughts are gold - dig for them
3. **No Leading**: Let them figure it out themselves
4. **Document Everything**: Capture the good and bad
5. **Comfort First**: Create a safe, non-judgmental space

**Remember**: The goal is to understand REAL user behavior, not to guide them toward "correct" usage. Their struggles, confusion, and frustrations are just as valuable as their successes.
